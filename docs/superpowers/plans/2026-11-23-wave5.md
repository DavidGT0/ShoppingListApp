## Review Focus
1. Logging in with an email stores the REAL username in the app, not the typed email. Otherwise the "נוסף ע״י" comparisons and the header break.
2. After a rename the old token stops working (the JWT `sub` is the username). The app must switch to the new token atomically, so the 3 s live refresh never fires with the old token and logs the user out.
3. A rename to an existing username, with any case or surrounding spaces, is refused with a Hebrew message. Renaming to your own current name is a no-op success.
4. Pull-to-refresh works in BOTH list modes, manual and by category, on Android.
5. Existing users whose username contains `@` (legacy) can still log in. Fall back to an exact username match when no email matches.

### Task W5-T1: Server: login with email, rename, connection check, log hygiene

**Files:**
- Modify:
  - `ShoppingListServer/main.py`
  - `ShoppingListServer/database.py` (`create_engine(..., pool_pre_ping=True)`)
  - `ShoppingListServer/email_sender.py` (log messages without the address)
- Test: `ShoppingListServer/tests/test_login_email.py`, `ShoppingListServer/tests/test_rename.py`

**Interfaces:**
- **`POST /token` (login):** accepts a username OR an email in the `username` form field.
  - If the value contains `@`, it looks up the email first (trimmed, case-insensitive) and falls back to `find_user_for_login`.
  - The response adds `username` (the canonical username): `{access_token, token_type, username}`.
  - The 401 message stays `"שם משתמש או סיסמה שגויים"`.
- **`PATCH /users/me` (rename):**
  - Body `{ "username": str }`, trimmed.
  - It is refused with 400 and a Hebrew message when:
    - the name is empty;
    - the name contains `@`: `"שם המשתמש לא יכול להכיל @"`;
    - the name is longer than the registration limit (use the same limit registration enforces, or 50 if none);
    - the name is taken case-insensitively by another user: `"שם המשתמש כבר תפוס"`.
  - On success it returns `{access_token, token_type, username}` with a NEW token for the new name.
  - Renaming to the same name returns 200 with a fresh token.
- **`POST /register`:** now also refuses `@` in the username, with the same message.
- **`email_sender`:** the warning and exception logs no longer include the recipient. Example: `"RESEND_API_KEY is not set - email was not sent"`.

### Task W5-T2: App: pull-to-refresh, login with email, rename, segmented sort control

  - `src/screens/SettingsScreen/SettingsScreen.js` + styles

**Interfaces:**
- Consumes: W5-T1's endpoints.
- **Pull-to-refresh: root cause.** The list uses `ScrollView` (category mode) and `DraggableFlatList` (manual mode). Both are gesture-handler components. RNGH's ScrollView and FlatList only cooperate with a `refreshControl` they can attach a gesture ref to. The code passes React Native's own `RefreshControl` (category mode) or `refreshing`/`onRefresh` props (manual mode), so the gesture-handler scroll view swallows the release.
  - Fix: import `RefreshControl` from `react-native-gesture-handler` and pass it as the `refreshControl` prop in BOTH modes, removing `refreshing`/`onRefresh` from `DraggableFlatList`.
  - Test: both modes render a `refreshControl` whose element type is RNGH's `RefreshControl`, and whose `onRefresh` triggers a refresh.
- **Login:**
  - The username field label and placeholder become `שם משתמש או אימייל`, and the accessibility label is updated to match.
  - `auth.login` stores `data.username` from the server response, not the typed text. If the server omits it, fall back to the typed text.
- **Rename in Settings:**
  - Show the current username with an edit button (testID `edit_username_button`). It opens an inline field (`username_input_settings`) with save (`save_username_button`) and cancel.
  - `auth.changeUsername(newName)` calls `PATCH /users/me`. On success it writes the new token and username to AsyncStorage before resolving, and the screen shows the new name.
  - No logout and no navigation.
  - Errors show the server's Hebrew message.
  - Client-side, refuse an empty name or one containing `@` before calling, with the same Hebrew messages.
- **Segmented sort control:**
  - It replaces the "סדר ידני / לפי מחלקות" text toggle with two equal segments, `סדר ידני` and `לפי מחלקות`.
  - Each segment has an icon: `drag-horizontal-variant` or `format-list-bulleted` for manual, `shape-outline` for categories. Verify the names against the glyph map.
  - The active segment is filled with `colors.primary` and white text. The inactive one is white with `colors.primary` text and border.
  - testIDs `sort_segment_manual` and `sort_segment_category`, each with `accessibilityRole="button"` and `accessibilityState={{ selected }}`.
  - The mode persistence (`@sort_mode_<listId>`) and behaviour are unchanged.
