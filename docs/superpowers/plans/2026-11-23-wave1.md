## Global Constraints
- **Hebrew:** every user-facing string, from the server and in the app, is in Hebrew.
- **No emails:** never return or display a user's email.
- **Live refresh must keep working:** `useLiveRefresh` (default export) plus the screen's `mutationVersion`/`pendingMutations` guard, through `startMutation()`/`endMutation()`. Every new mutation goes through the guard.
- **Tables:** new tables are allowed, since `create_all` creates them. **No new columns on existing tables in wave 1.**
- **TDD and checks:** red before green. Server is `pytest`, app is `npx jest`. Lint is 0 errors and ≤12 warnings.
- **Line endings and BOM:** match git. No `sed -i`.
- **Commits:** local only, plain English messages, no AI attribution, no personal info.
- **Environment:** `C:/SLA/.superpowers/sdd/round2/environment.md` covers the commands and worktree notes.

## Review Focus
1. A pending (undo-able) delete must never reappear because of a live refresh. It must be committed if the user leaves the screen or backgrounds the app.
2. Undo after a purchase toggle must restore exactly the previous state, even if a live refresh ran in between.
3. Suggestions must not show items already in the current list, and must not leak another user's history.
4. Duplicating a list shared with you creates a list YOU own. The original is untouched.
5. "Send as text" of an empty list (or one where everything is bought) shows "אין מוצרים לשליחה" and doesn't open the share sheet.

### Task A2: Product history, suggestions, and bulk purchased actions (server)

**Files:**
- Modify: `ShoppingListServer/models.py`, `ShoppingListServer/main.py`
- Create: `ShoppingListServer/tests/test_suggestions.py`, `ShoppingListServer/tests/test_purchased_bulk.py`

**Interfaces:**
- Produces:
  - **New table** `models.ItemHistory` (`item_history`), with columns:
    - `id` (PK)
    - `user_id` (FK users, index)
    - `name` (String(100), as typed most recently)
    - `name_key` (String(100), `name.strip().lower()`)
    - `use_count` (int, default 1)
    - `last_used` (DateTime)
    - A `UniqueConstraint(user_id, name_key)`.
    - `User.item_history` relationship with cascade delete-orphan, so account deletion removes it.
  - `add_item` upserts the history for `current_user`: increment `use_count` and update `last_used` and `name`.
  - `GET /items/suggestions?q=&list_id=` returns `[str]`.
    - At most 8 names, from the current user's history only.
    - Order: names whose `name_key` starts with `q.strip().lower()` first, then names that contain it. Within each group, `use_count` desc, then `last_used` desc.
    - An empty `q` returns the top 8 by `use_count`.
    - When `list_id` is given (the user must have access, else 403/404), exclude names already in that list's NOT-purchased items, compared case-insensitively and trimmed.
  - `POST /lists/{list_id}/purchased/restore` sets `purchased=False` on all purchased items. Returns `{"restored": int}`.
  - `POST /lists/{list_id}/purchased/clear` deletes all purchased items. Returns `{"deleted": int}`.
  - Both require owner or member. A stranger gets 403 and a missing list gets 404, with the existing Hebrew messages from `get_accessible_list_or_error`.

    - another user's history is never returned
    - deleting the account removes the history
    - a stranger's `list_id` gets 403
  - **Bulk:**
