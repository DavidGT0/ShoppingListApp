# Redesign plan: the route, "now in the department", light or dark, editable departments

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:**
- A new look for the whole app.
- In "by department" mode, the list is a route of departments with a "עכשיו במחלקה" focus card and a progress ring.
- Light, dark or system theme, chosen by the user.
- A check circle and a trash icon instead of swipes.
- Per-list editing of department names, icons and order, shared by all members.

**Architecture:**
- **Themes:** a `ThemeProvider` exposes `{ mode, colors, setMode }`. Styles become `makeStyles(colors)` functions, used through a small `useStyles(makeStyles)` hook that memoises per palette.
- **Server:** a `list_category_settings` table plus `PUT /lists/{id}/categories/layout`.
- **App:** `resolveCategory` applies the list's layout (names, icons, order).
- **List screen:** the "by department" mode is rebuilt as a route.

**Tech Stack:** React Native 0.86, react-native-gesture-handler 3.1.0, react-native-draggable-flatlist 4.0.3, react-native-vector-icons, AsyncStorage v3, FastAPI, SQLAlchemy, pytest, Jest. There is no react-native-svg, so the progress ring is built from Views.

**Spec:** `docs/superpowers/specs/2026-11-23-redesign-design.md`. It is approved. Read the section "Questions from the builder check, with my decisions".

## Global Constraints
- **Every earlier constraint still applies:**
  - Hebrew user-facing text.
  - TDD.
  - The stale-response guard (`startMutation`/`endMutation`).
  - Wave-3 offline blocking: `blockIfOffline` comes first in every mutation, and `failedOffline` goes in its catch.
  - Wave-4 accessibility: Hebrew labels and roles. Never put `accessibilityState.disabled` on a control that must still show the offline alert.
  - Wave-5 behaviour: the gesture-handler `RefreshControl` in both modes, and `dragHitSlop` on the drag list.
  - Lint: 0 errors, ≤12 warnings.
  - LF line endings and BOM kept per file.
  - Local commits with no attribution, and no personal data.
- **Terminology:**
  - The word is **"מחלקות"** / **"מחלקה"**. Never "תחנות".
  - The exact strings are `לפי מחלקות`, `עכשיו במחלקה`, `עריכת מחלקות` and `הכל בעגלה 🎉`.
- **Brand colours:**
  - Primary `#1E6FE8`, secondary/success `#1FC9A3`, navy `#0F172A`.
  - Dark palette: background `#0B1220`, surface `#111A2E`, raised surface `#1E293B`, text `#E2E8F0`, secondary text `#94A3B8`, border `#334155`.
  - Text on any background must meet AA (4.5:1).
- **Theme modes:**
  - `@theme_mode` takes `light`, `dark` or `system`, and the default is `system`.
  - `system` follows `useColorScheme()`.
- **No regressions.** All of these must keep working:
  - undo, suggestions, units and notes, "נוסף ע״י"
  - offline mode, live refresh, manual drag ordering
  - the bought section with its two buttons, members, the ⋮ menu, share-as-text, duplicate
  - all wave-4 accessibility
- **Don't change:** the Appium test (`tests/test_shopli.py`), and category colours/keywords in `services/categories.js`. You may add an `icon` field per built-in department.
- **Verification on the phone:** the controller installs the build over USB after each wave and the user checks it. There is no emulator.

## Review Focus
1. Dark mode: no text, icon or border keeps a hard-coded light-theme colour. Add a source scan: no hex literal outside `theme/` and `services/categories.js`, and no `colors.` import from `theme/colors` inside a component. Everything goes through the theme hook.
2. The focus card always shows the first department in the list's layout order that still has unbought items. When the last unbought item in it is checked, it moves to the next. When nothing is left, it shows `הכל בעגלה 🎉`.
3. Removing the swipes must not remove any capability:
   - Marking bought is the circle.
   - Deleting is the trash icon, with undo.
   - Editing is a tap on the name.
   - Un-buying works from the bought section.
4. Department layout saved by one member appears for another member through the live refresh, with no reopen.
5. Editing departments offline is blocked with the existing alert. Changing the theme offline works.

## Wave 7: department layout per list (server and data)

### Task R7-T1: server `list_category_settings` and the layout endpoint

**Files:**
- Modify: `models.py`, `main.py` (and `schema_upgrade.py` only if you add columns to existing tables).
- Test: `tests/test_category_layout.py`

**Interfaces:**
- **Table `list_category_settings`:**
  - Columns: `id`, `list_id` (FK, cascade), `key` (String 40: a built-in key or `custom:<id>`), `name` (String 30, nullable), `icon` (String 16, nullable), `position` (Integer).
  - Unique on (`list_id`, `key`).
- **`custom_categories.icon`:** String 16, nullable. Add it through `schema_upgrade.ensure_columns`.
- **`GET /lists/{id}/categories`:** returns `{ "custom": [...existing shape + icon], "layout": [{key, name, icon, position}] }`.
  - This is a breaking shape change, so the app task updates the client in the same wave.
  - Members and the owner both have access.
- **`PUT /lists/{id}/categories/layout`:**
  - Body: `{ "layout": [{key, name?, icon?}] }`. The array order is the order.
  - Replaces the list's settings.
  - Rejected with 400 in Hebrew: an unknown key; a name longer than 30 or empty after trim; `other` not last.
  - Keys that no longer exist are ignored.
  - Open to any member.
- **`POST /lists/{id}/categories`:** accepts an optional `icon` (default `🛒`).
- **Duplicate list:** copies the layout, remapping custom keys to the new custom ids.
- [ ] **Step 1: failing tests**
  - get/put round trip
  - a member can save
  - a stranger gets 403
  - the validation errors
  - `other` stays last
  - duplicate copies and remaps
  - deleting a custom category removes its layout row
- [ ] **Steps 2–5:** commit `Per-list department layout: names, icons and order`.
