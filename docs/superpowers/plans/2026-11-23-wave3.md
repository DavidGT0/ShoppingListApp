# גל 3 — תוכנית עבודה (צפייה בלי אינטרנט)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** When the phone has no connection, the user still sees the last saved lists and items, with a clear banner. Every edit is blocked with a clear Hebrew message. There is no offline queue.

**Architecture:** A small cache module over AsyncStorage. The screens load from the server and write the cache on success. On a network error they fall back to the cache and switch to an `offline` mode that disables mutations. The live refresh brings them back online automatically.

**Tech Stack:** React Native 0.86, AsyncStorage v3 (`getItem`/`setItem`/`removeMany`/`getAllKeys`), Jest.

**Spec:** `docs/superpowers/specs/2026-11-23-improvements-round-2-design.md`, the section "גל 3 … 4".

## Global Constraints
- Every wave 1/2 global constraint still applies: Hebrew, the mutation guard and live refresh, TDD, lint ≤12, line endings and BOM, local commits with no attribution.
- **Cache keys:** `@cache_lists`, `@cache_items_<listId>`, `@cache_categories_<listId>`. The values are the JSON of the server responses.
- **Offline is triggered ONLY by network errors** (`error.network === true` from `http.js`). A 4xx or 5xx is not offline. A 401 stays a session expiry, and a 403/404 stays lost access.
- **Banner text (exact):** "אין חיבור לאינטרנט — מוצגת הגרסה האחרונה שנשמרה".
- **Blocked-edit alert (exact):** `Alert.alert('אין חיבור לאינטרנט', 'אפשר רק לצפות ברשימה עד שהחיבור יחזור')`.
- **Logout, session expiry and account deletion** must remove every `@cache_*` key.

## Review Focus
1. A failed request that is NOT a network error must never flip the screen into offline mode or show cached data.
2. When the connection returns, the next successful refresh clears the banner and re-enables editing without any user action.
3. No mutation request is ever sent while offline. All entry points are covered: add, chips, toggle, delete and undo, amount, edit, drag, restore/clear, categories, members, the menu actions, create, join, rename and duplicate.
4. Opening the app with no network and a saved token shows My Lists from the cache, and doesn't throw.
5. Another user's cached lists never appear after logout and login.

**Files:**
- Create: `ShoppingListFront/src/services/offlineCache.js`, `ShoppingListFront/__tests__/offlineCache.test.js`
- Modify: `ShoppingListFront/src/services/auth.js` (logout and deleteAccount clear the cache), `ShoppingListFront/src/services/http.js` (clear the cache on session expiry)

**Interfaces:**
- Produces:
  - `saveCache(key, data)`, `readCache(key) -> data|null` (a corrupt JSON value gives null), and `clearAllCaches()`, which removes every key starting with `@cache_`.
  - `cacheKeys.lists`, `cacheKeys.items(listId)`, `cacheKeys.categories(listId)`.
  - `loadWithCache(fetcher, key) -> Promise<{data, fromCache: boolean}>`:
    - on success, save to the cache and return `{data, fromCache:false}`;
    - on `error.network`, read the cache, and return `{data: cached, fromCache:true}` if there is one, otherwise rethrow;
    - on any other error, rethrow without touching the cache.

  - `loadWithCache`: success writes the cache; a network error with a cache returns `fromCache`; a network error with no cache rethrows; a 500 error rethrows and doesn't read the cache
  - logout, `deleteAccount` and session expiry clear the caches

**Interfaces:**
- Consumes: W3-T1.
- Produces:
  - `<OfflineBanner visible />`, with `testID="offline_banner"` and the exact text.
  - Each screen has an `isOffline` state:
    - The initial load and every refresh go through `loadWithCache` for items/lists and categories.

    - A successful server response sets `isOffline=false`.
    - Any mutation handler that runs while `isOffline` shows the blocked alert and returns BEFORE `startMutation`, without calling the API.
    - A mutation that fails with `error.network` sets `isOffline=true` and shows the blocked alert, instead of the generic error alert.
  - **Visuals while offline:** `AddItemInput` is not editable and shows no chips. The swipe and amount buttons are disabled. The menu, members and join entry points show the blocked alert.
  - **Undo:** a pending delete whose commit fails with `error.network` brings the item back and shows the blocked alert.
